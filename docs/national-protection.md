# 国保标签与选目规则

本项目的“国保”专指国务院公布的**全国重点文物保护单位**。它是保护身份，不是世界遗产、日本国宝、全国重点寺院或景区等级，也不代表图版质量或个人到访状态。

## 标签如何确定

- 卡片和详情标明“第几批国保”。批次按**所绘主体首次被公布或纳入合并项目**记录，不能拿合并后母单位的最早批次替代。公布日期来自通知落款，不用网页转载日期。
- 正式单位名称与产品显示名可以不同。登记同时保留所绘主体、正式单位名、关系（独立单位 / 组成部分 / 合并项目）、官方来源、名单定位和核对日期。
- 只画寺院的一殿、一塔或一尊造像时，核实它属于该单位；不能把同寺的后来重建建筑或附近遗迹自动一起算作国保。重建、已毁复原图尤其要核对保护对象。
- 组合图可以对应多个单位或批次：西安大小雁塔各保留登记；正定开元寺分别显示第三批钟楼、在第六批并入的须弥塔。同批重复标签合并展示，原始登记不丢失。
- `unconfirmed` 表示尚未核实，**不是认定“不属于国保”**；`related_site` 表示相关遗址的身份不能直接转授给所绘对象；`not_applicable` 用于日本等不适用中国制度的条目。不确定就不贴国保标签，不从知名度或一般“文保单位”描述推断。
- 搜索支持“国保”“第三批国保”“第3批国保”以及正式单位名。合并说明里的母单位批次不作为本主体的批次搜索命中。

## 新录入如何参考名单

1. 按用户约定省区，从官方名单（含增补、合并项目）筛出候选。先按正式名称、别名、地点、保护范围与现有目录去重，避免一寺多名重复收录；寺内不同主体是否另立条目由产品范围决定。
2. 优先补齐当前收录的地域、时代和建筑类型缺口。兼顾地方代表性、存世形制和图鉴辨识度，不只选最知名景点，也不按批次先后排“价值榜”。
3. 按资料就绪程度安排：有可靠主体照片、年代与所绘范围依据的先进入生成队列；证据欠缺的记清缺口，继续其他就绪项。资料搜索沿用增量手册预算，不为每个候选从头穷尽全国名单。
4. 在批次计划记录每项的正式国保单位名、批次、所绘主体对应关系与官方来源；未确认写未确认。国保身份只是选目参考，省保、市保和其他有价值遗存仍可收录，**不能成为原型制图的新增等待门槛**。
5. 对已接入目录的条目维护下面的源数据，重建国保前端资料。照片、原件、设色和用户验收仍按[增量制图手册](monument-batch-workflow.md)推进，本规则不恢复 AI 审图或技术质量拦截，也不授权增加代理、修改个人记录、提交或发布。

## 数据维护与命令

唯一维护入口为 [national-protection.json](../assets/research/national-protection.json)：

- `sources`：批次、官方 URL、公布日期、实际下载日期与下载内容 SHA-256。哈希用于考据追溯，不是图版验收。
- `entries.<id>[]`：`batch`、`unitName`、`relation`、`scope`、`source`、`locator`；合并项目补 `parent`（原单位名及批次）、`note`，必要时补 `scopeSources`。定位的“PDF 第N页”是从1开始的文件页面，不一定等于公报印刷页码；没有可靠页码时写附件、地域及单位名，不猜编号。
- `untagged.<id>`：未贴原因及状态。核实后移到 `entries`；不使用自创批次0或“非国保”标签。新 ID 尚未考据时可留待核对，不阻塞制图；交付说明如实列出未知项。

```bash
node scripts/prepare-protection.mjs
node scripts/prepare-protection.mjs --check
node --test tests/*.test.cjs
git diff --check
```

第一条命令仅生成 `protection-data.js`；第二条只读检查生成结果是否过期。修改国保资料**不需要运行任何图版生成或转码脚本**。同步更新首页与详情页的受影响资源缓存版本；浏览器检查标签、来源、批次搜索及窄屏换行，保留所有个人记录与图片验收状态。
